# Agent Note: 全模型共享的精简执行策略

Status: implemented

[English](2026-08-16-shared-model-execution-policy.md) | 中文

## Problem

长周期科研请求同时包含部署 persona、项目权威、Goal 指引、工具指引和召回证据。若自主推进、确认、资源与用户纠正规则在多个段落重复出现，重复的谨慎措辞会显得比当前用户请求更具权威，导致无谓确认循环，或让模型把可修改 monitor 当成人类明确纠正之上的权威。

请求前意图分类器会在每个有效 loop 之前增加一次模型调用、延迟、成本和新的易错决策。为不同 provider 维护多份策略还会让同一执行行为随模型路由漂移。

## Decision

`@deepseek-ai/dsh-model-execution-policy` 在 order 5 为每次模型请求注册同一段稳定提示词。Sol、DeepSeek、Luna、诊断组装与未来路由均接收完全相同且不依赖 provider 的措辞。

该段落把每条通用执行规则只陈述一次。只读请求检查并汇报；change、fix、continue 与 resume 请求直接执行范围内本地工作和非破坏性验证。模型只在缺失选择会实质改变结果，或动作必然涉及外部写入、破坏、购买或扩大范围时提问。当前用户纠正会结束相应操作歧义；研究合同被修改时建立新的可追溯版本，而不是继承旧合同结论。

警告、后台进程和资源使用在测得因果干扰或命中当前用户确认阈值之前只是观测。真实平台和工具拒绝仍具约束力。Goal 与科研控制提示只保留各自领域的权威和生命周期规则，因此通用执行策略只有一个模型可见归属。

该策略遵循 OpenAI 的 GPT-5.6 指引：保持提示精简、每条指令只说一次、紧凑定义自主边界，并且只为重要歧义提问。组装过程不增加分类器或路由分支。

## Alternatives considered

**在 Goal 与科研状态插件重复规则。** 拒绝，因为长会话会放大重复的谨慎措辞，并使其与最新请求竞争。

**维护多份 provider 专用策略。** 拒绝，因为目标执行语义是共享的，重复文本只会产生漂移，不能改善请求判断。

**每个 step 前增加 LLM 分类器。** 拒绝，因为意图和确认边界可以直接陈述；额外调用会增加延迟、token 成本和与执行模型分歧的新来源。

**在 runtime 代码里强制所有语义选择。** 拒绝，因为代码可以执行真实 sandbox、工具与 Goal 状态转换，却无法判断资源观测是否因果污染科学结果，也无法替用户判断某次纠正是否改变实验合同。

## Consequences

每条模型路由都收到一段短且前缀稳定的控制文本。策略不增加工具、持久状态、模型调用、路由查询或阻塞阶段。模型遵从仍有概率性，因此确定性组装和真实 AgentLoop 测试固定请求文本，受控行为回放测量模型结果。平台执行约束与用户请求范围保持不变。
