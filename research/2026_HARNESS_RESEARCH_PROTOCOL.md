# Pi Idea Harness 研究与验证协议（2026）

更新：2026-08-13

## 1. 核心命题

本轮不把“上下文组装有用”当作既定事实，而把它写成可证伪假设：

> 在主模型、任务、工具权限和总输入预算固定时，以“逐字权威目标 + 当前任务 + 相关证据与冲突 + 最近原始轨迹”为核心的上下文组装，相比完整历史、仅保留尾部或单一全局摘要，能够提高长任务的完成率、方向保持与证据使用正确率，并降低昂贵模型 token 与等待时间。

“合理”不是一个算法名，而是五个独立变量：

1. **身份保持**：权威 P0 与路线版本不被摘要或检索改写。
2. **任务充分性**：当前动作所需的约束、对象、完成条件和引用都存在。
3. **证据相关性**：支持、反对、冲突和失效条件按当前任务选择。
4. **局部连续性**：保留最近尚未闭合的原始轨迹，避免摘要切断正在进行的推理。
5. **干扰控制**：完成后的工具细节、重复日志、过期假设和不相关记录退出活动上下文，但仍可追溯。

如果组装减少了 token，却降低任务成功率、漏掉否决证据或增加方向偏移，则假设在该条件下失败。

## 2. 研究范围

只纳入能改变 Harness 端到端性能的机制：

- 长上下文、压缩、检索、记忆与冲突处理；
- 可学习或演化的 Skill、Workflow 和工具经验；
- 强/弱模型路由、工作段接管与成本控制；
- 多 Agent 分解、并行执行、合并和验证；
- Agent–Computer Interface、工具契约与结构化状态；
- 可观测性、评测、失败归因、恢复与安全边界。

不因为论文提出了一个功能就加入产品。候选机制必须至少改善一项：任务成功率、方向保持、token、延迟、并发吞吐、恢复能力或风险；并说明对其他指标的代价。

## 3. 证据等级

| 等级 | 范围 | 如何使用 |
|---|---|---|
| A | 2024–2026 顶会/顶刊正式论文，且有相关消融或多任务实证 | 可作为默认设计的重要依据，仍需本项目小规模复验 |
| B | 正式会议 Findings、Datasets/Benchmarks Track、TMLR 或顶会 Workshop | 用于失败模式、边界和补充机制，不单独决定架构 |
| C | arXiv/在审论文、官方工程博客、公开实现 | 作为实现线索或待验证假设，必须明确标注 |
| X | 来源、作者、场次或结果无法核验 | 禁止引用和实现背书 |

每条论文记录至少包含：正式状态、主要机制、实验对象、效应量、最相关消融、限制、能否迁移到 Pi，以及直接来源。

## 4. 文献检索与纳入规则

主要来源限定为 ACL Anthology、PMLR、NeurIPS Proceedings、ICLR/OpenReview、MLSys Proceedings、TMLR/OpenReview 和论文作者的正式代码仓库。技术结论优先使用论文与 proceedings，不用二手博客替代。

核心检索概念：

- `agent context management`, `context compression`, `context interference`, `long-horizon memory`；
- `agent workflow memory`, `skill library`, `self-improving agent`, `experience reuse`；
- `multi-agent failure`, `parallel software agents`, `task decomposition`, `orchestration`；
- `model routing`, `cascade`, `small model collaboration`, `agent efficiency`；
- `agent interface`, `tool use evaluation`, `sandbox`, `event sourced agent state`。

纳入条件：2024–2026；正式可核验；机制与 Harness 有直接关系；至少给出可比较的结果或严谨失败分析。更早论文只在它仍定义关键问题时进入背景。

排除条件：仅靠自报产品指标；没有任务级结果；把增加调用次数当成性能提升；不可核验截图；与机器人控制等场景的迁移链条过长；只展示单例而无对照。

## 5. 产品级评价指标

### 5.1 正确性

- **End-to-end success**：由确定性测试、最终状态或预先固定 rubric 判定。
- **Idea retention**：最终动作是否仍服务 P0 的科学对象与终点标准。
- **Constraint satisfaction**：当前权限、非目标、版本和否决路线是否被遵守。
- **Evidence fidelity**：引用正确率、冲突保留率、反面证据召回率。
- **Regression / repair**：已完成内容是否被后续轮次破坏；失败后能否恢复。

### 5.2 效率

- 主模型 input/output/cache token；
- Luna input/output/cache token；
- 端到端延迟、首个有效结果时间和并发加速比；
- 上下文编译 CPU 时间、峰值内存和派生存储大小；
- 模型调用数、handoff 数、重试数和重复工具操作数。

### 5.3 失败条件

以下任一发生时，不因 token 节省而宣称机制有效：

- P0 被改写、截断或被派生记忆覆盖；
- 否决证据或未解决冲突被静默删除；
- 在共享文件或依赖任务上并发导致冲突/回归；
- 未验证 Skill 被自动提升为生产能力；
- Luna 失败触发递归调用、无界重试或阻塞主对话；
- 使用模型自评代替可获得的确定性验证。

## 6. Luna 总预算与运行守卫

本目标全部基准的 Luna 硬上限为 **100,000,000 tokens 总计**，不是单次额度。计入 `input + output + cacheRead + cacheWrite`，以 Pi 返回的 provider usage 为准；若 provider 缺字段，同时保存本地估算但不得用估算放宽硬上限。

执行器必须：

1. 在每个请求前按最坏输入和 `maxTokens` 预留额度；不足则拒绝启动。
2. 请求完成后把真实 usage 追加到唯一 ledger，并释放未使用预留。
3. 同一 ledger 使用文件锁或单进程调度，避免并发超支。
4. 缓存命中不重复计费，但记录缓存来源与 prompt 哈希。
5. 默认先做不超过 1,000,000 tokens 的 pilot；只有发现稳定差异且方差不足以判断时才扩大。
6. 任何实验不得调用 Sol；模型固定为 `openai-codex/gpt-5.6-luna`。

当前目标的 Codex 自身消耗尽量控制在 10,000,000 tokens 内，并通过 Goal usage 定期检查。

## 7. 实验矩阵

### 7.1 上下文组装（首要）

在同一批长任务轨迹上比较：

1. **Full Raw**：完整历史，超出固定预算则判不可执行，不静默截断。
2. **Recent Tail**：只保留最近若干轮。
3. **Global Summary + Tail**：单一摘要加最近轨迹。
4. **Block Retrieve**：分工作块摘要、相关检索加最近原文。
5. **Structured Assembly**：P0 + 当前任务包 + 相关证据/冲突 + 最近原文；即项目假设。
6. **Oracle Minimum**：人工生成的最小充分上下文，只作为性能上界，不是可部署方案。

题目分为事实回忆、冲突判别、下一步选择、代码修改、回归修复和方向诱导六类。每类都放入：过期事实、同名干扰、后来否决、来自工具的长噪声，以及一条只存在于早期的关键反证。

主要判定：Structured Assembly 的 end-to-end success 和 Idea retention 必须高于或不劣于最佳可部署基线，同时显著减少活动输入；不能只报告 recall。

### 7.2 Skill 学习

比较无 Skill、未经验证的经验摘要、经测试提升的原子 Skill、含污染/过期 Skill。考察复用收益和错误经验传播。只有“候选 → sandbox eval → admission → versioned install → canary → rollback”路径可进入实现建议。

### 7.3 多 Agent / 并行代码

任务按依赖图预先分层：

- 无共享写集的独立文件/独立测试：允许并行；
- 只读共享、写集分离：允许并行后确定性合并；
- 共享文件、接口未冻结或强顺序依赖：保持单执行者。

比较单 Luna 顺序执行、窄任务包并行、自由聊天式多 Agent。主要指标为正确完成时间、总 token、合并冲突、回归和需要主控制者重新解释的次数。并行必须是“添加证据/产物”，不能覆盖 Idea 或控制权。

### 7.4 路由与接管

比较全程强模型的历史基线、逐步强弱模型切换、以及一次发放有限工作段后由 Luna 连续执行。当前目标不调用 Sol，因此只实现 Luna 侧协议和确定性 gate；强模型收益以现有真实记录或后续经用户授权的评测验证。

## 8. 统计与停止规则

- 先固定题目、答案、随机种子、prompt 模板和评分脚本，再运行模型。
- 条件顺序随机化；同一题目的上下文内容相同，仅组装策略变化。
- 报告均值以外还报告题目级配对差、失败样本和 bootstrap 置信区间。
- pilot 若某机制被另一机制在正确率、token 和延迟三项同时支配，则停止扩样。
- 发现方向错误、预算账本异常或递归重试立即停止整组实验。
- 不用 Luna 给自己的输出打最终分；能用 schema、单元测试、引用 ID 或预先答案判定时必须确定性评分。

## 9. 预期可证伪边界

上下文组装不应被描述成普遍提高所有任务性能。预期它在以下条件下最有价值：历史长、目标稳定、证据散落、冲突演化明显、工具日志多、当前任务只依赖历史的一小部分。

在短对话、所有历史都与当前问题强相关、需要逐字综合整篇材料，或检索器无法识别关键关联时，完整上下文可能相等或更好。实验必须保留这些反例，避免把“压短”误当成“组装正确”。
